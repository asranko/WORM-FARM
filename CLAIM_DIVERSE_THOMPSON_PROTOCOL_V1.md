# WORM FARM — Claim-Diverse Thompson vs Fixed-Rule Protocol v1

## Purpose

Test whether the current Thompson-routing advantage persists across genuinely different tasks rather than repeated stochastic executions of one synthetic claim.

## Status

**DESIGN ONLY — NOT EXECUTED**

No result from this protocol may be used as evidence until execution is completed.

## Task set

Create **12 independently authored synthetic claims** spanning materially different reasoning structures.

Minimum categories:

1. causal inference;
2. counterfactual reasoning;
3. boundary-condition detection;
4. assumption discovery;
5. anomaly detection;
6. evidence sufficiency;
7. mechanism discrimination;
8. competing explanations;
9. uncertainty calibration;
10. adversarial claim;
11. novelty / hypothesis construction;
12. multi-step reasoning.

No claim may be generated by a fixed seed-substitution template.

Each task receives a permanent task ID and SHA-256 text hash.

## Stochastic replication

Use:

```text
15 seeds × 12 tasks
```

for a total of 180 seed-task executions per policy.

Each task must be evaluated under multiple seeds so seed-level noise can be separated from task-level variation.

## Policies

Compare exactly two policies:

```text
A: Thompson Sampling + empirical specialty×mode signal
B: Simple fixed-rule baseline
```

No Adaptive Bias.
No RL.
No Meta-Routing.
No other model changes.

## Construction / evaluation split

Use bidirectional task-level holdout:

### Fold A

```text
6 tasks → rule construction
6 unseen tasks → evaluation
```

### Fold B

```text
other 6 tasks → rule construction
first 6 tasks → evaluation
```

The rule-selection procedure must see only the construction tasks.

Thompson receives only the allowed training/history available under the protocol.

## Primary endpoint

```text
G7 routing_mean_fitness
```

## Primary analysis

Use task-level paired summaries, not raw decision count.

For each task:

```text
mean over the 15 seeds
```

Then compare Thompson vs Simple Rule across the 12 task units.

Report:

- mean paired difference;
- median paired difference;
- Cohen d_z at task level;
- 95% paired bootstrap CI;
- number of task wins / losses / ties.

## Secondary endpoint

Audit-pass rate.

## Required diagnostics

Before acceptance, report:

- unique task count;
- unique task text count;
- seed × task matrix;
- task-level variance;
- between-task variance;
- within-task seed variance;
- whether any task is repeated across construction/evaluation in the same fold;
- task-hash uniqueness;
- source of each task.

## Acceptance rule

A claim of task-level robustness requires:

```text
both bidirectional folds completed
AND
CI excludes zero in the predefined direction
AND
the effect is evaluated at task level
AND
no task leakage is present
```

A failure does not retract prior seed-level findings; it limits their scope.

## Critical anti-patterns

Do NOT:

- generate all tasks from one textual template;
- use seed number as pseudo-task identity;
- tune the task list after seeing outcomes;
- select “interesting” tasks post hoc;
- count repeated decisions as independent tasks.

## Release gate

Only after this protocol succeeds may the project use language equivalent to:

```text
"Thompson routing shows evidence of task-level generalization
within the defined synthetic benchmark."
```

Even then, no claim of universal optimality is permitted.
